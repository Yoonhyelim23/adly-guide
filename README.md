# ADLY 이용 가이드

ADLY 사용자 이용 가이드 웹페이지 소스입니다.

## 폴더 구조

```
adly-guide/
├── index.html      ← 가이드 본문 (이 파일을 편집)
├── images/         ← 가이드에 들어가는 이미지 파일
├── README.md       ← 이 문서
└── .gitignore
```

- 예전에는 이미지가 HTML 안에 통째로 들어가 있어 파일이 56MB였지만,
  이미지를 `images/` 폴더로 분리해 HTML이 약 140KB로 가벼워졌습니다.

## 편집 방법

### 1. 글/문구 수정
- `index.html`을 편집기(VS Code 등)나 GitHub 웹에서 열어 수정합니다.
- 가이드는 상단/좌측 메뉴로 나뉜 여러 "탭"으로 구성되어 있습니다.
  - `id="tab-intro-*"`  : 1. 소개
  - `id="tab-start-*"`  : 2. 시작하기
  - `id="tab-setup-*"`  : 3. 이용설정
  - `id="tab-asset-*"`  : 4. 자산 연결
  - `id="tab-faq"`      : FAQ
- 담당 챕터의 탭 영역만 수정하면 다른 사람과 충돌이 거의 없습니다.

### 2. 이미지 교체/추가
- 새 이미지는 `images/` 폴더에 넣습니다. (파일명 자유, 예: `setup-step1.png`)
- HTML에서 `<img src="images/파일명.png">` 형태로 연결합니다.
- 이미지 용량이 크면 미리 압축(TinyPNG 등)해서 넣어주세요.

### 3. 미리보기
- `index.html`을 브라우저에서 더블클릭하면 바로 확인할 수 있습니다.
  (이미지가 파일로 분리되어 있어 서버 없이도 열립니다.)

## 협업 규칙 (Git)

- `main` 브랜치에 직접 push하지 않습니다.
- 작업은 브랜치를 만들어 진행하고, Pull Request(PR)로 리뷰 후 병합합니다.
  ```
  git checkout -b edit/자산연결-업데이트
  # ... 수정 ...
  git add .
  git commit -m "자산연결 챕터 문구 수정"
  git push -u origin edit/자산연결-업데이트
  # GitHub에서 PR 생성
  ```
- GitHub 웹에서 편집하는 경우, 파일 편집 후 "새 브랜치로 커밋" 옵션을 선택하면 자동으로 PR을 만들 수 있습니다.

## 개발 전달 방법

- 수정이 완료되면 `index.html` + `images/` 폴더를 함께 전달합니다.
- 개발은 이 두 가지를 사내 서버(가이드 도메인 경로)에 업로드합니다.
- HTML의 이미지 경로는 상대경로(`images/...`)이므로, 두 개를 같은 위치에 올리면 됩니다.
