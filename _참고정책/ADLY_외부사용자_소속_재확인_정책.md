# 외부 사용자 소속 재확인 및 변경 처리 정책

## 1. 문서 목적

외부 사용자(광고주·대행사)가 현재도 ADLY에 등록된 회사에 소속되어 있는지 주기적으로 재확인하고, 퇴사·이직 등으로 소속이 변경된 경우 기존 회사의 광고주·자산·솔루션에 더 이상 접근하지 못하도록 한다.

소속 변경이 확인된 사용자는 ADLY 및 연동 솔루션 이용을 즉시 중지하고, 사용자 본인이 기존 계정을 탈퇴한 후 새로운 소속 정보로 재가입하도록 안내한다.

시스템이 사용자를 강제로 탈퇴시키지는 않는다.

> 본 정책은 사용자의 퇴사·이직 등 개인의 소속 변경을 확인하기 위한 정책이다. 회사와 ADLY 간 계약 종료는 회사·광고주 단위 이용 중지 정책에서 별도로 처리한다.

---

## 2. 적용 대상

| 구분 | 적용 여부 | 비고 |
| --- | --- | --- |
| 광고주 | 적용 | 사용자 상태가 `승인`인 경우 |
| 대행사 | 적용 | 사용자 상태가 `승인`인 경우 |
| 임직원 | 미적용 | 기존 임직원 재직·권한 관리 정책 적용 |

### 2-1. 적용하지 않는 경우

다음은 소속 변경으로 처리하지 않는다.

- 동일 회사 내 담당 업무 또는 부서만 변경된 경우
- 담당 영업자만 변경된 경우
- 동일한 사업자·법인이 유지된 상태에서 회사명만 변경된 경우
- 등록된 회사명에 단순 오기재가 있는 경우
- 회사와 ADLY 간 이용 계약만 종료된 경우

단, 합병·분할 등으로 실제 소속 사업자 또는 법인이 달라진 경우에는 소속 변경으로 처리한다.

## 3. 상태 관리 원칙

### 3-1. 기존 사용자 상태

기존 사용자 상태 5개는 변경하지 않는다.

| 사용자 상태 | ADLY 로그인 | 기본 솔루션 이용 기준 |
| --- | ---: | ---: |
| 승인대기 | O | X |
| 승인 | O | 소속 확인 상태에 따라 결정 |
| 반려 | O | X |
| 정지 | X | X |
| 탈퇴 | 기존 회원정보로 이용 불가 | X |

> 탈퇴한 회원정보로는 서비스에 접근할 수 없다. 다만 동일한 SNS 계정으로 인증한 후 신규 가입 화면에 진입할 수 있다.

### 3-2. 소속 확인 상태

사용자 상태와 별도로 `소속 확인 상태`를 관리한다. 한 사용자는 아래 세 상태 중 하나만 가질 수 있다.

| 소속 확인 상태 | 시스템 값 | 의미 |
| --- | --- | --- |
| 확인 완료 | `CONFIRMED` | 사용자가 현재 소속이 동일하다고 확인한 상태 |
| 재확인 필요 | `CHECK_REQUIRED` | 마지막 확인 후 6개월이 지나 재확인이 필요한 상태 |
| 소속 변경·탈퇴 대기 | `CHANGE_REPORTED` | 사용자 또는 운영자가 소속 변경을 신고·확인하여 이용이 중지된 상태 |

기존 정책안의 `소속 확인 필요 여부`와 `소속 변경 여부`처럼 예·아니요 값을 두 개로 나누어 관리하지 않는다. 이를 통해 `소속 확인 필요`와 `소속 변경`이 동시에 적용되는 모순을 방지한다.

### 3-3. 추가 관리 항목

| 항목 | 시스템 필드명 | 기본값 | 설명 |
| --- | --- | --- | --- |
| 소속 확인 상태 | `affiliationStatus` | `CONFIRMED` | 현재 소속 확인 단계 |
| 마지막 소속 확인일 | `lastAffiliationConfirmedAt` | 신규 승인 일시 | 마지막으로 소속 동일이 확인된 일시 |
| 소속 변경 신고일 | `affiliationChangedAt` | 없음 | 소속 변경 상태로 전환된 일시 |
| 소속 변경 처리 주체 | `affiliationChangedBy` | 없음 | `USER`, `SALES_MANAGER`, `SUPER_ADMIN` 중 하나 |
| 확인 회사명 | `affiliationConfirmedCompanyName` | 승인 당시 회사명 | 사용자가 확인한 당시의 회사명 기록 |

### 3-4. 상태 전환 기준

| 발생 상황 | 변경 결과 |
| --- | --- |
| 신규 이용설정 승인 | `확인 완료`, 마지막 소속 확인일=승인 일시 |
| 마지막 소속 확인 후 6개월 경과 | `재확인 필요` |
| 사용자가 `[소속 동일]` 선택 | `확인 완료`, 마지막 소속 확인일=현재 시각 |
| 사용자가 소속 변경을 최종 확인 | `소속 변경·탈퇴 대기`, 신고일·처리 주체 기록 |
| 운영자가 소속 변경 처리 | `소속 변경·탈퇴 대기`, 신고일·처리 주체 기록 |
| 운영자가 오선택을 복구하고 소속 동일까지 확인 | `확인 완료`, 마지막 소속 확인일=복구 시각 |
| 운영자가 오선택만 해제하고 소속 동일 여부는 확인하지 못함 | `재확인 필요` |

## 4. 실제 이용 가능 여부

솔루션 이용은 사용자 상태가 `승인`이고 소속 확인 상태가 `확인 완료`인 경우에만 가능하다.

| 사용자 상태 | 소속 확인 상태 | ADLY 로그인 | ADLY 내 이용 | 연동 솔루션 이용 |
| --- | --- | ---: | --- | ---: |
| 승인 | 확인 완료 | O | 정상 이용 | O |
| 승인 | 재확인 필요 | O | 재확인 모달만 우선 노출 | X |
| 승인 | 소속 변경·탈퇴 대기 | O | 제한적 이용 | X |
| 정지 | 무관 | X | X | X |
| 탈퇴 | 무관 | 기존 회원정보로 이용 불가 | X | X |

### 4-1. 연동 솔루션 차단 원칙

- 소속 확인 상태가 `재확인 필요` 또는 `소속 변경·탈퇴 대기`로 변경되는 즉시 ADLY와 모든 연동 솔루션의 신규 진입을 차단한다.
- ADLY 로그인 화면의 모달 노출만으로 차단하지 않으며, 연동 솔루션 접근 시에도 최신 이용 가능 상태를 확인한다.
- 이미 로그인되어 있거나 연동 솔루션 화면을 열어 둔 경우에도 다음 권한 확인 시점부터 이용할 수 없도록 기존 세션·토큰 또는 권한 정보를 갱신한다.
- 권한 정보 전파에 실패한 경우 재처리하고, 최종 실패 건은 운영자가 확인할 수 있도록 기록·알림 처리한다.

## 5. 재확인 주기 및 대상 선정

### 5-1. 확인 주기

- 기준일: 마지막 소속 확인일
- 주기: 달력 기준 6개월
- 기준 시간대: 한국 표준시(KST)
- 대상: 사용자 유형이 광고주 또는 대행사이고, 사용자 상태가 `승인`이며, 소속 확인 상태가 `확인 완료`인 사용자
- 처리: 마지막 소속 확인일로부터 6개월이 되는 날의 00:00(KST) 이후 배치에서 `재확인 필요`로 변경

배치는 동일 사용자를 중복 처리하더라도 상태나 확인일이 잘못 변경되지 않도록 한다. 배치 실패 시 다음 실행에서 미처리 대상을 다시 처리한다.

### 5-2. 기존 승인 사용자 최초 적용

정책 시행 이전에 이미 승인된 사용자는 과거 승인일이 아닌 `정책 적용일`을 마지막 소속 확인일의 초기값으로 설정한다.

대상자가 많은 경우 정책 적용일을 사용자별로 분산하여 재확인 요청이 특정 시점에 집중되지 않도록 할 수 있다.

## 6. 프론트 정책

### 6-1. 소속 재확인 모달

#### 노출 조건

- 사용자 상태: `승인`
- 소속 확인 상태: `재확인 필요`
- 노출 시점: ADLY 로그인 직후
- 외부 영역 클릭 또는 X 버튼으로 닫을 수 없음
- 사용자가 응답하기 전까지 ADLY 주요 기능과 연동 솔루션을 이용할 수 없음

#### 화면 문구

```text
소속 정보 재확인

현재도 아래 회사에 소속되어 ADLY를 이용하고 있는지 확인해주세요.

퇴사하거나 다른 회사로 이직한 경우에는
[소속이 변경되었습니다]를 선택해주세요.

담당 영업자만 변경된 경우에는 [소속 동일]을 선택한 후
이용설정에서 담당 영업자 정보를 변경해주세요.

회사명 변경 또는 등록 정보 오류는 탈퇴하지 말고
담당 영업자에게 문의해주세요.

등록된 회사: ㈜ABC컴퍼니

[등록 정보 문의]  [소속 동일]  [소속이 변경되었습니다]
```

`등록된 회사`에는 연결 광고주명이 아닌 사용자가 이용설정 시 등록한 회사명을 표시한다.

#### 선택 결과

| 선택 | 처리 |
| --- | --- |
| `[소속 동일]` | 소속 확인 상태를 `확인 완료`로 변경하고, 마지막 소속 확인일과 확인 회사명을 현재 기준으로 저장한 후 정상 이용 |
| `[소속이 변경되었습니다]` | 즉시 상태를 변경하지 않고 소속 변경 최종 확인 모달 노출 |
| `[등록 정보 문의]` | 담당 영업자 문의 방법 안내. 소속 확인 상태는 `재확인 필요`로 유지되며 정보 확인 전까지 솔루션 차단 유지 |

### 6-2. 소속 변경 최종 확인 모달

사용자의 단순 오선택을 방지하기 위해 상태를 변경하기 전에 한 번 더 확인한다.

```text
소속 변경 확인

소속 변경으로 처리하면 ADLY 및 연동 솔루션 이용이 즉시 중지됩니다.
처리 후에는 사용자가 직접 [소속 동일] 상태로 되돌릴 수 없습니다.

정말 소속 변경으로 처리하시겠습니까?

[돌아가기]  [소속 변경으로 처리]
```

| 선택 | 처리 |
| --- | --- |
| `[돌아가기]` | 재확인 모달로 돌아가며 상태 변경 없음 |
| `[소속 변경으로 처리]` | 소속 확인 상태를 `소속 변경·탈퇴 대기`로 변경하고 신고일과 처리 주체 `USER`를 기록한 후 연동 솔루션 이용 즉시 차단 |

상태 저장에 실패한 경우 상태를 변경하지 않고 오류 메시지를 노출한다. 중복 클릭이나 재요청이 발생해도 동일한 처리 결과가 유지되어야 한다.

### 6-3. 탈퇴 안내 모달

소속 확인 상태가 `소속 변경·탈퇴 대기`로 변경된 직후와 이후 로그인 시마다 노출한다.

```text
소속 변경 안내

소속이 변경된 경우 기존 계정의 탈퇴가 필요합니다.
탈퇴 후 동일한 계정으로 재가입하여
새로운 소속 정보로 이용설정을 다시 등록해주세요.

• ADLY 및 연동 솔루션의 이용 권한이 종료됩니다.
• 시나리오·자산 등의 업무 데이터는 각 솔루션의 정책에 따라 처리됩니다.
• 회원정보는 개인정보처리방침에 따라 파기되며, 보관이 필요한
  일부 기록은 정해진 기간 동안 보관 후 파기됩니다.
• 탈퇴 후 동일한 계정으로 재가입할 수 있으나 기존 회원정보와
  권한은 복구되지 않습니다.

지금 탈퇴하지 않더라도 ADLY 및 연동 솔루션 이용은 계속 중지됩니다.

[나중에 탈퇴]  [탈퇴하기]
```

| 선택 | 처리 |
| --- | --- |
| `[탈퇴하기]` | 기존 탈퇴 정책에 따라 탈퇴 처리하고 탈퇴 사유를 `AFFILIATION_CHANGED`로 기록한 후 로그아웃 및 로그인 페이지 이동 |
| `[나중에 탈퇴]` | 모달 닫기. 이용 차단은 유지하며 다음 로그인 시 탈퇴 안내 모달 재노출 |

### 6-4. 소속 변경·탈퇴 대기 상태의 이용 범위

| 항목 | 가능 여부 |
| --- | ---: |
| ADLY 로그인 | O |
| 연동 솔루션 이용 | X |
| 이용설정 조회 | O, 읽기 전용 |
| 이용설정 수정·변경 요청 | X |
| 내 정보 조회 | O |
| 내 정보 수정 | X |
| 회원탈퇴 | O |
| 사용자가 소속 동일로 되돌리기 | X |

사용자는 내 정보와 기존 이용설정을 조회하거나 회원탈퇴를 할 수 있으며, 이용설정 수정 및 연동 솔루션 이용은 할 수 없다.

### 6-5. 탈퇴 진입 경로와 사유

소속 확인 상태가 `소속 변경·탈퇴 대기`인 사용자가 탈퇴하면, 탈퇴 안내 모달 또는 `내 정보 > 회원탈퇴` 중 어느 경로로 진입하더라도 탈퇴 사유를 `AFFILIATION_CHANGED`로 기록한다.

## 7. 어드민 정책

### 7-1. 조회 및 표시

| 항목 | 정책 |
| --- | --- |
| 사용자 목록 필터 | `소속 재확인 필요`, `소속 변경·탈퇴 대기` 필터 제공 |
| 기간 검색 | 소속 변경 신고일 기준 기간 검색 제공 |
| 사용자 상세 라벨 | `소속 재확인 필요` 또는 `소속 변경·탈퇴 대기` 표시 |
| 사용자 상세 정보 | 소속 확인 상태, 마지막 확인일, 변경 신고일, 처리 주체, 확인 회사명 표시 |
| 탈퇴 사유 | `자발적 탈퇴`와 `소속 변경 탈퇴`를 구분하여 표시 |

### 7-2. 역할별 처리 권한

| 처리 항목 | Sales Manager | Super Admin |
| --- | ---: | ---: |
| 매핑된 사용자 소속 상태 조회 | O | O |
| 소속 변경 상태로 수동 전환 | O, 매핑된 사용자만 | O |
| 재확인 필요 상태 수동 설정 | X | O |
| 소속 변경 오선택 복구 | X | O |
| 전체 대상 조회·필터 | X | O |

Sales Manager가 사용자의 퇴사·이직 사실을 확인한 경우 해당 사용자를 `소속 변경·탈퇴 대기` 상태로 전환할 수 있다. 이때 처리 사유 입력은 필수이며 사용자 접근은 즉시 차단한다.

접근을 다시 허용하는 복구 처리는 Super Admin만 수행할 수 있다.

### 7-3. 오선택 복구

| 확인 결과 | 복구 처리 |
| --- | --- |
| 현재도 등록된 회사에 소속된 사실을 운영자가 확인함 | `확인 완료`로 변경, 마지막 소속 확인일=복구 시각, 솔루션 이용 복구 |
| 실제 소속 여부를 확인하지 못함 | `재확인 필요`로 변경, 사용자 재로그인 시 재확인 모달 노출 |

오선택 복구 시 사유를 필수로 입력하고 처리자, 처리 일시, 이전 상태, 변경 상태를 기록한다.

### 7-4. 수동 처리 공통 원칙

- 모든 수동 설정·복구는 사유 입력을 필수로 한다.
- 처리자, 처리 일시, 이전 값, 변경 값, 처리 사유를 변경 이력에 기록한다.
- 상태 변경과 연동 솔루션 차단·복구 결과를 함께 확인할 수 있어야 한다.
- 일부 연동 솔루션 반영에 실패하면 재처리하고 최종 실패 건은 Super Admin에게 알린다.

## 8. 다른 사용자 상태와의 관계

제한 수준이 서로 다른 상태가 동시에 존재하는 경우 더 강한 이용 제한을 우선 적용한다.

| 상황 | 처리 원칙 |
| --- | --- |
| 재확인 필요 상태에서 사용자가 정지됨 | 소속 확인 상태와 이력은 유지하고 로그인 차단 |
| 소속 변경·탈퇴 대기 상태에서 사용자가 정지됨 | 소속 변경 상태와 이력 유지, 로그인과 솔루션 모두 차단 |
| 정지 해제 후 소속 상태가 재확인 필요 | 로그인 후 재확인 완료 전까지 솔루션 차단 |
| 정지 해제 후 소속 상태가 소속 변경·탈퇴 대기 | 탈퇴 안내만 제공하고 솔루션 차단 유지 |
| 반려 사용자가 재신청 후 승인됨 | 승인 일시를 최초 소속 확인일로 설정하고 `확인 완료` 처리 |
| 탈퇴 사용자가 동일 계정으로 재가입함 | 기존 회원 상태를 복구하지 않고 신규 회원으로 처리 |

## 9. 탈퇴 처리

### 9-1. 탈퇴 사유

| 값 | 설명 | 적용 기준 |
| --- | --- | --- |
| `VOLUNTARY` | 자발적 탈퇴 | 소속 확인 상태가 `소속 변경·탈퇴 대기`가 아닌 사용자가 내 정보에서 탈퇴 |
| `AFFILIATION_CHANGED` | 소속 변경 탈퇴 | 소속 확인 상태가 `소속 변경·탈퇴 대기`인 사용자의 모든 탈퇴 |

### 9-2. 탈퇴 시 처리 항목

탈퇴는 별도의 `ADLY 회원탈퇴 정책`을 따른다. 소속 변경 탈퇴 시에도 다음 항목을 동일하게 적용한다.

- 사용자 상태를 즉시 `탈퇴`로 변경
- ADLY 세션 종료 및 로그아웃
- ADLY 및 연동 솔루션 권한 회수
- 광고주·자산 접근 권한 종료
- 요청 중인 이용설정·변경 요청이 있는 경우 요청 취소 처리
- 자산 요청은 별도 취소 상태를 만들지 않으며 기존 처리 이력을 유지하되 탈퇴 사용자의 접근은 종료
- 회원정보 파기 및 법적·운영상 보관 대상 이력 분리 보관

하위 솔루션 권한 회수에 일부 실패하더라도 ADLY 탈퇴와 접근 차단을 되돌리지 않는다. 실패 건은 재처리하고 최종 실패 시 운영자에게 알린다.

> 상세 처리 기준은 실제 개발 시점의 `ADLY 회원탈퇴 정책` 최신 버전을 참조한다.

---

## 10. 재가입

- 탈퇴 후 동일한 SNS 계정으로 다시 가입할 수 있다.
- 재가입 시 새로운 회원 식별자를 발급하고 신규 회원으로 처리한다.
- 이전 회원의 광고주·자산·솔루션 권한과 이용설정 정보는 자동으로 연결하거나 복구하지 않는다.
- 동일한 이메일 또는 동일한 SNS 계정이라는 이유만으로 이전 권한을 복구하지 않는다.
- 새로운 소속 정보로 이용설정을 제출하고 승인 절차를 다시 진행한다.
- 어드민에서는 과거 탈퇴 회원과 신규 재가입 회원을 구분하여 확인할 수 있어야 한다.

---

## 11. 이력 및 로그

다음 이벤트를 사용자 변경 이력 또는 운영 로그에 기록한다.

- 배치에 의한 `소속 재확인 필요` 전환
- 사용자의 `소속 동일` 응답
- 사용자의 `소속 변경` 응답
- 운영자의 소속 변경 수동 처리
- 운영자의 오선택 복구
- 연동 솔루션 차단·복구 결과
- 탈퇴 처리 결과 및 탈퇴 사유

소속 동일 응답 시 사용자가 확인한 회사명을 당시 값으로 함께 기록한다. 이후 회사명이 변경되더라도 과거에 어떤 회사 정보를 확인했는지 식별할 수 있어야 한다.

로그와 이력의 보관 기간은 개인정보처리방침 및 기존 ADLY 로그 보관 정책을 따른다.

## 12. 예외 상황 처리

| 상황 | 처리 |
| --- | --- |
| 퇴사 후 새로운 소속이 없음 | `소속이 변경되었습니다` 선택 후 기존 계정 탈퇴 |
| 동일 회사 내 담당 영업자만 변경됨 | `소속 동일` 선택 후 이용설정에서 담당 영업자 변경 |
| 동일 회사 내 업무·부서만 변경됨 | `소속 동일` 선택. ADLY 이용이 더 이상 필요하지 않으면 담당 영업자에게 권한 조정 요청 |
| 동일 사업자·법인의 회사명만 변경됨 | `등록 정보 문의`를 통해 운영자 확인 후 회사명 수정 및 `확인 완료` 처리 |
| 회사명 단순 오기재 | `등록 정보 문의`를 통해 운영자 확인 후 정보 수정 |
| 합병·분할로 소속 사업자·법인이 변경됨 | 소속 변경 처리 후 탈퇴·재가입 |
| 회사와 ADLY 간 계약만 종료됨 | 본 정책이 아닌 회사·광고주 단위 이용 중지 정책 적용 |
| 응답 저장 중 오류 발생 | 상태 변경 없이 오류 안내 후 재시도 |

## 13. 운영 알림

- `소속 변경·탈퇴 대기` 상태로 전환된 사용자는 어드민 필터를 통해 조회할 수 있어야 한다.
- 사용자가 소속 변경 신고 후 탈퇴하지 않은 경우에도 솔루션 이용 차단은 계속 유지한다.
- 장기간 미탈퇴 사용자의 후속 안내가 필요한 경우 사용자와 담당 Sales Manager에게 안내 메일을 발송할 수 있도록 대상 추출이 가능해야 한다.

## 15. 핵심 정책 요약

1. 기존 사용자 상태 5개는 유지한다.
2. 소속 확인 단계는 `확인 완료`, `재확인 필요`, `소속 변경·탈퇴 대기` 중 하나로 별도 관리한다.
3. 사용자 상태가 `승인`이고 소속 확인 상태가 `확인 완료`인 경우에만 연동 솔루션을 이용할 수 있다.
4. 소속 재확인이 필요하거나 소속 변경이 신고된 경우 ADLY와 연동 솔루션 접근을 즉시 차단한다.
5. 소속 변경 사용자를 시스템이 강제로 탈퇴시키지는 않지만, 탈퇴 전까지 이용 차단을 유지한다.
6. 탈퇴 후 동일 계정으로 재가입할 수 있으나 기존 권한과 데이터는 자동 복구하지 않는다.
